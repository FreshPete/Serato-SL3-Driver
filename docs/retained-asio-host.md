# Retained-device ASIO host

The ASIO host now has an explicit retained-device lifetime. The production configuration provider selects it; the temporary inspection/single-open diagnostics remain separate. Initialization acquires one isolated native worker/device and verifies its actual clock. Successful Stop retires audio I/O and callbacks while keeping that same device ready. Buffer disposal/recreation and later Start use fresh audio queues without releasing/reopening the redirect. Final close releases the device/process and seals this owner against reacquisition.

The latest native open also has a [nonwaiting guard against overlapping cooperating redirect owners](redirect-owner.md). It covers independent objects/diagnostics, not safe sequential reacquisition or transport sharing across final Release. Its new 48-test build has software evidence only; the physical results below retain their original binary identities.

**The archived 578A worker passed the two-stream native retained test.** [Physical result and limits](retained-physical-test.md). The latest protocol-v2 [idle control-inspection extension](held-controls.md) has software/simulated coverage and needs fresh native validation. Current COM/IASIO tests use an explicitly simulated worker. The new production path is built but no configuration, measured timing profile or COM/ASIO registration is installed. Earlier physical eight-interval evidence belongs to its archived build and does not certify this new lifetime.

## Ownership contract

`WorkerSpec::lifetime` selects temporary or retained operation. Production configuration fixes retained operation rather than accepting a user-supplied test mode. Retained hello must match the separate protocol and native kind before acquire; neither simulated nor legacy handshakes can advertise native readiness.

`HostSession::inspect()` in retained mode acquires once and publishes only the worker's fresh observed clock. Repeated successful inspection retains that lease. Start requires prepared planes, a healthy ready control session and retired previous audio ownership. It creates a new data mapping/audio owner and sends that identity to the same worker. The worker re-reads its clock on the held native handle before alternate activation/submission. A mismatch preserves the actual changed rate and first failure cause, releases the session and admits no callback. No rate setter or implicit retry runs.

Successful Stop requests callback-gate closure before asking the worker to retire audio. Its report distinguishes a still-held ready device from final device/process release. Buffer changes require either a healthy held ready device with retired audio/I/O or complete process/audio retirement. A blocked callback keeps its planes leased even after native I/O stops; start, inspection and disposal cannot reuse them. Callback reentry into stop/close/buffer/control operations is rejected before modifying owner state.

The host closes each successful old data mapping only after its audio thread retires. The worker detaches its retired peer view without prematurely closing the host-owned mapping. This lets an already executing callback return into its old queue, even after final native release, while no new native output can be submitted from that retired stream. Those queues are never reused. Genuine stream failures still close/fault the data channel and force final release.

The callback gate's atomic first close distinguishes a live worker failure from process exit observed after an already requested stop. A later bank in the same batch cannot turn orderly final release into a spurious worker-exited fault. Real unexpected worker exit and throwing callbacks retain the existing failure behavior.

Publishing a new Start also invalidates the host's earlier idle I/O-retirement flag before waiting for its reply. If startup stalls or its reply is lost, the old ready snapshot cannot certify new I/O retirement. The last decoded snapshot remains historical; host ownership flags stay unknown until a fresh typed cleanup reply proves otherwise. Hung-start/submission tests assert this distinction even after the private process exits.

Explicit final close drains/releases under the existing shared bounded deadline, independently observing I/O/device, process/job and audio-thread retirement. An idle owner destructor attempts ordinary final release. A destructor with executing/unretired audio keeps the existing nonwaiting containment path: it never terminates a host callback thread; shared audio state retains its planes, channel, process handle and DLL code until actual retirement. Native helper/kernel calls can still exceed the watchdog's requested process-termination deadline; no stronger Windows teardown guarantee is inferred.

The facade accepts a normal stopped-but-held session and immediately releases a retained device if initialization finds a timing-profile rate mismatch. Startup failure invalidates facade metadata and requires orderly cleanup/reopening the driver. The timing-profile gate, fixed reviewed bank/rate, source/binary pinning, owner-only mappings and original Rane registration separation remain in force.

## Verification

Subsequent [object-recreation coverage](asio-recreation-tests.md) now checks metadata-only enumeration release followed by two fresh COM objects, each with setup and ordinary stream I/O. Exact simulated worker audits prove three acquisitions/releases, seven clock reads and four audio begin/end pairs. This is actual unregistered-DLL software coverage; safe physical reacquisition remains unproved.

`sl3_retained_host_tests` uses actual private processes and SDK callback planes. An audit proves exactly one acquisition/final release across repeated eight-/64-interval streams and buffer recreation, with a fresh clock read and target for every start. It checks fresh callback frame positions, stable active planes, non-reentrant control, final sealing, idle destruction, blocked Stop, blocked final Close and owner destruction. Clock changes, failed/partial/hung acquisition/start, throwing callbacks, native-kind mismatch, asserted absent-helper native rejection and prompt release after profile mismatch are covered. Unknown cleanup is not rewritten as device release.

`sl3_asio_retained_session_tests` invokes the actual unregistered DLL's COM/IASIO vtable. It initializes, runs repeated sessions, rejects 240-frame banks and retries preferred 128-frame banks, disposes/recreates buffers and retires normally. It then destroys the last IASIO object and releases caller/factory DLL references while a callback is deliberately blocked. The DLL and original planes stay valid until that callback returns; its independent audio-module lease then retires. Test timing data remains explicitly synthetic. The production-provider test consumes adjacent pinned synthetic records and rejects a truthfully simulated worker at the new native-shaped handshake, before clock/device access.

Release/Debug, SDK-free, Python and exact build/source/log bindings are recorded in [build evidence](evidence/retained-asio-host-build.json). Historical worker-only verification now uses its immutable `retained-device-worker-20261030` checkpoint and exact source reconstruction from commit `abd4586`, so the old positive simulation cannot silently be attributed to the new host implementation.
