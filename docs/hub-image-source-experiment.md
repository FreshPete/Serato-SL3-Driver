# Source-only logging experiment

An attended attempt has now run and failed its query GUID check, then stopped/deleted its collector and observed absence. Its saved ETL provides [separate image-window metadata](attended-hub-image.md), not a passing source-only run. The original failed records and exact query/controller/action bytes are frozen. The query helper now [retains rejected metadata while still failing](image-source-session-query.md); the actual returned GUID from the old attempt cannot be reconstructed from its error log and is not invented.

A [1 November follow-up](attended-logging-20261101.md) now exercises the new committed readback and retained native rejection on a real source: the persisted configuration retains the requested GUID, but the native session returns a different GUID with the expected private name/output. Cleanup and independent absence pass. The one-approval launcher works, while the strict source diagnostic remains failed. This does not retrofit the missing earlier GUID or validate timer expiry.

`scripts/test-hub-image-source.py` prepares the next attended experiment for the loaded hub identity gap. Default invocation only prints a plan. Explicit `--run` requires a directly queried elevated token and never launches a UAC prompt. It creates and starts one private persisted PLA collector set, observes its ETW session through the separate read-only query helper, then stops it if necessary and deletes the owned collector configuration. It never opens the SL3, submits audio or changes driver/security/firmware settings.

The implementation is prepared, not live-validated. Five software policy tests pass. Four actual CLI cases check the parent default plan, internal action default plan, invalid preparation role and rejection of a run under the current limited token. Both plan modes and that refused run create no context or capture root. PowerShell parsing reports no errors. No persistent collector or logging session was created by these checks.

The cleanup absence handler has since been corrected for PowerShell's signed hexadecimal literals: the normalized unsigned HRESULT must be compared with `0x80300002L`, not the negative Int32 literal `0x80300002`. `scripts/test-hub-image-cleanup-errors.ps1` extracts the actual production catch body and recognizes an actual missing-collector query, rejects an unrelated error, recognizes a nested HRESULT, and reproduces the old defect with the original literal. All four checks pass; the five policy tests still pass. This tests error classification without creating, stopping or deleting a collector. It does not validate the operational cleanup branch on a real persisted source.

The controller suite now passes **39 targeted cases**, including thirty-four whole-controller simulations. They replace child execution and token inspection in the test process; placeholder child files and deliberately invalid simulated ETL bytes are confined to temporary directories and never executed or decoded. Cases cover observation/cleanup, startup uncertainty, preexisting-source refusal, failed cleanup, supervisor stop, loss, missing ETL, late queries, output escapes, rejected/contradictory query metadata and committed-configuration evidence. Each case rereads the generated report and keeps timer cause, image rundown and USB readiness unproved. Rejected query files remain hashed evidence, never accepted observations. Eleven helper parser/query-boundary cases pass separately. These simulations establish software behavior, not actual PLA lifecycle success or valid simulated ETL contents.

The parent freezes the preparation bytes in a new context, pins its scripts and calls the established full XML/validation-only preflight immediately before creation. The internal action writes an absence-admission record before `Commit(1)` (`plaCreateNew`) and queues `Start(false)`. Queuing is not reported as a live start; only a successful independent query can establish that observation. Microsoft's [Start contract](https://learn.microsoft.com/en-us/windows/win32/api/pla/nf-pla-idatacollectorset-start) distinguishes queuing from actual start and requires the root output directory to exist. The action creates that private root after validation/commit if necessary.

Before queuing Start, the action now creates a separate COM object, queries the committed service collector and saves `start.json.committed.json`. This records its status, bounded full XML, query outcome and comparison with the frozen preparation. It requires one collector/provider and exact critical identity, path, timing, output, mode and provider fields, with GUID/path normalization. A mismatch or failed readback prevents the Start request; cleanup still uses its prior ownership admission. The snapshot is saved before Start so it can survive a later child timeout. The parent requires the fixed snapshot filename, exact hash and accepted inactive configuration; missing, escaped, changed or rejected evidence fails even if the child claims success. This readback observes persisted configuration, not native live properties or successful GUID forwarding. It has not run against a newly committed real collector. Fifteen cases exercise the extracted production comparison without COM; the controller cases also simulate timeout after a snapshot is saved. The next attended experiment must still collect real service and native observations.

Each action child has a 12-second wait limit; each query child has a three-second limit. After the start action returns, the parent watches for up to configured Duration plus eight seconds, polling about every quarter-second between queries. A query that returns after that watch deadline fails. The configured source Duration remains five seconds in the retained preparation. These limits bound the controller's waits; killing a timed-out child does not prove cancellation of an outstanding Windows service request.

The observer must see an active source, the system-logger bit, QPC clock and output within the private capture root. It rejects observed circular, append, real-time and process-private modes and nonzero sampled loss counters. It then requires disappearance before its own cleanup stop. Disappearance can result from failure as well as Duration expiry, so `independentStopValidated` stays false and no timer cause is inferred. `successful` means the bounded observation/cleanup checks and a bounded ETL artifact passed; it does not mean rundown, timer cause or USB readiness passed.

Cleanup requires the exact prior admission record and matching persisted collector session name, GUID and root path. It refuses to clean a collector that failed absence admission. If the matching collector is not stopped, cleanup requests synchronous stop before deletion. Errors, action timeouts, failed cleanup and unknown start outcomes are retained in the context report/logs. A final independent query must report absence. This is still point evidence; service quiescence after an uncertain asynchronous request is unproved. Capture files are preserved for inspection; they are never deleted by this runner.

Use a fresh preparation and context from an already elevated terminal when attended testing is appropriate:

```powershell
pwsh -NoProfile -File scripts/prepare-hub-image-source.ps1 -Output analysis/new-image-source.json
.venv/Scripts/python.exe scripts/test-hub-image-source.py --preparation analysis/new-image-source.json --context tests/results/local/image-source-attended-01
# Review the plan, then explicitly run the same experiment:
.venv/Scripts/python.exe scripts/test-hub-image-source.py --preparation analysis/new-image-source.json --context tests/results/local/image-source-attended-01 --run
```

The parent output context must be a new direct or nested path beneath the existing `tests/results/local` directory, and its parent must exist. Neither the context nor the prospective capture root may already exist. Every attempted run is single-use; never reuse a failed context or preparation. The private collector is transiently persisted only during an actual run. No schedules, tasks or security settings are added.

At most four ETL files, each nonempty and at most 64 MiB, are hashed for retained evidence. Oversized, empty or unexpected artifacts cause failure while keeping cleanup/reporting separate. The requested PLA file-size setting is best-effort rather than a hard disk quota. ETL presence and sampled counters do not prove final trace loss statistics, correct kernel image rundown or loaded hub identity. The [existing offline rundown checker](kernel-image-rundown.md) and service/event evidence must resolve those questions before this source can qualify a future USB test. Safe successive SL3 acquisition remains unresolved.

The [explicit observed/rechecked native GUID policy](native-session-guid-recheck.md) now supplies an opt-in next diagnostic, grounded in the captured 1 November distinction. Default configured-GUID rejection and the original failed records remain unchanged. Its candidate is not an accepted observation; a separate strict query must confirm it, and later GUID changes fail. The new mode is software-tested and awaits its own live result.
