# Fresh clock observations across ASIO objects

Recreated ASIO objects now obtain a fresh read-only clock observation from the already-held device before publishing metadata. Previously the explicit owner scope reused its first acquisition's cached rate for subsequent metadata objects. A new object can now observe a changed rate and reject it when it does not match the bound timing profile, without releasing/reacquiring the SL3 or sending a rate setter.

The retained worker accepts optional IPC command `0x307` only after handshake and acquisition, in its idle `ready` phase with retired I/O and no stream. It returns the existing typed Snapshot after validating the fresh `read_rate()` result. This is not a USB command number: the native device uses its existing interrupt rate getter. Request bodies must be empty. Getter failure retires its I/O and releases the device, or the isolated worker contains unretired storage according to the existing adapter contract.

`HostSession::inspect_rate()` additionally refuses when client buffers are prepared. It marks prior retirement evidence unknown before publishing a request, updates the observed rate only after a successful validated held-device reply, and closes/seals the host owner on attempted-query failure. It never acquires, retries, changes rate or accepts the old cached value as a successful reply. Guard refusals themselves perform no I/O. Audio-thread calls remain refused.

First IASIO init still gets its clock from acquisition. Subsequent facade objects in that same scope refresh the held clock; repeated init on the same already-initialized facade stays idempotent. Every actual stream begin continues to verify the clock separately. A bound profile mismatch closes the device before failed init returns. ASIO rate setters and supported bank sizes are unchanged, and no unmeasured timing record is created.

The command extends protocol v3's operation set while retaining its existing hello and Snapshot wire layouts. Old workers reject unknown commands; an unsuccessful refresh must fail and close rather than fall back to cached metadata. Current native configuration still pins the exact tested worker hash. Old-worker positive interoperability is not claimed.

Software checks cover a simulated clock change between metadata objects, profile mismatch, injected refresh failure with no cached success, idle-buffer refusal, pre-acquisition/closed-owner refusal, malformed request bodies, active-audio refusal and independent final device/process retirement. The actual unregistered COM/IASIO shared-scope audit now requires **one acquisition, seven clock reads, four audio begin/end pairs and one final release**. Two additional reads belong to the recreated metadata objects. The full Release suite passes **48/48**. [Bound build/test evidence](evidence/facade-scope-build-20261101.json).

No physical refresh or new SL3 operation was run. Rate accuracy, physical continuity/audio quality, measured timing, current Serato admission and native scope validation remain incomplete. Historical physical captures retain their own worker identities.
