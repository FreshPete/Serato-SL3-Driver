# Explicit ASIO factory scope controller

**Later broker configuration:** with [reviewed broker records](broker-configuration.md), this factory scope denotes a client attachment to an external owner. First initialization attaches to that already-held session; successful EndScope certifies the client scope's callback/I/O/connection retirement and does not certify physical release or exit of the external worker. The private-worker format retains the physical/job semantics described below.

The production COM factory now exposes the project-owned optional `DeviceScope` interface, IID `0CF4A2E1-6610-4A5E-A751-E96431D08C92`. An in-process control host can keep one acquired device across enumeration and successive IASIO objects by retaining **the same factory**. This bounds the [shared owner's](facade-owner-scope.md) lifetime with ordinary COM references and explicit shutdown. It does not create a service, global cache or background driver session.

The controller queries the factory for this interface and calls `BeginScope` before its first `CreateInstance`. Begin pins the existing reviewed native configuration, helper/worker hashes and timing-file leases, but launches no worker and opens no USB device. First successful IASIO init acquires. All objects created through this factory receive that fixed scope/configuration; competing active borrows remain rejected. A factory already used for ordinary creation cannot be switched into scoped mode.

After releasing its IASIO objects, the controller calls `EndScope`. A borrowed owner returns `S_FALSE` without being closed. An unborrowed owner returns `S_OK` only after independent audio, I/O, device and private-process/job retirement checks. Failure returns `E_FAIL` and never restores the factory's default private-open path. A closed factory rejects further object creation and cannot begin another scope. `LockServer` retains its original semantics and does not acquire or begin a scope.

Factory/controller references keep `DllCanUnloadNow` false through the existing object lease. Devices hold their own scope reference, so releasing the controller before a live device does not tear down its connection. The last healthy idle device then closes the orphaned owner; existing nonwaiting callback retirement still handles destructive active-object release. The factory mutex is not held through worker/callback retirement. A device created but not initialized before scope end cannot acquire afterward.

The actual factory, interface identity and lifetime code are compiled into both production and the unregistered fixture DLL. Positive tests substitute only the existing simulated configuration/worker provider. They validate one acquisition, seven clock reads (including the later [metadata refreshes](retained-clock-refresh.md)), four audio begin/end pairs and one final release across three scoped IASIO objects, plus preparation without worker launch, begin-once rules, busy close, forbidden fallback, controller-first release, orphaned-owner final release and unopened-device rejection after close. Another scenario destroys a scoped object during a blocked callback: destruction returns without waiting, the callback retains its planes, scope end reports failure and the factory refuses fallback/reacquisition. The production DLL's real configuration path is tested negatively with an absent adjacent configuration, before any helper/device operation. All **48 Release tests** passed; no test provider export appears in the production DLL. [Source/binary-bound evidence](evidence/facade-scope-build-20261101.json).

The production default remains one private owner per object. The inspected [current Serato backends](serato-asio-object-lifetime.md) call ordinary `CoCreateInstance` separately and do not know this new project interface. Holding a factory in another process would not share this in-process owner with Serato. Adopting this mechanism in current Serato therefore still needs a genuine backend integration or a separately implemented interprocess transport/controller; this feature alone does not solve that requirement. No DLL injection, application/descriptor/account patch, registration, installation or native USB operation ran here.

Native scope reuse, real input/output mapping, measured timing, successive host lifetimes, current Serato admission and two-deck DVS remain incomplete.
