# One device owner across ASIO object recreation

`DriverOwner` now separates the acquired worker's lifetime from an individual `DriverFacade`. An explicit control scope can hold the owner while enumeration and successive audio objects are destroyed and recreated. This addresses the unnecessary release/reacquire pattern implicated by the [saved USB handoff evidence](attended-port-lifecycle-20261101.md), without depending on the original Rane stack becoming ready between objects.

The owner is lent exclusively. A second facade constructor is rejected while another facade borrows it, and explicit owner close returns no result while borrowed. Dropping a healthy, idle facade disposes any remaining idle buffers and returns the borrow; the retained worker stays acquired. Every subsequent stream uses the existing fresh data-channel/audio-owner lifecycle and rechecks the actual clock before audio begins. The later [clock-refresh extension](retained-clock-refresh.md) also obtains a fresh getter result for each recreated metadata object, replacing the first scope implementation's cached metadata reuse.

The controlling scope closes the owner explicitly once all facade borrows have ended. Close seals it against further borrowing. Failed acquisition, active stream destruction, a blocked callback or incomplete buffer retirement also seals the owner: nonwaiting shutdown closes callback admission, channels and the private process domain without claiming native I/O recovery. Executing callbacks retain their original planes and code leases until actual thread retirement. Shutdown now seals both retained and temporary inspection/checked-start entry points.

The ordinary constructor still creates a private owner per facade. The [optional production factory controller](factory-scope-controller.md) now supplies an explicit COM/module lifetime and shutdown boundary when a control host begins a scope before object creation. The default provider has not been switched to persistent ownership. There is no global cache, idle expiration, silent reacquisition, registry change or deployment. Reviewed configuration-file leases and timing provenance remain required. Sharing this in-process C++ owner does not implement an external broker or multi-client audio, and current Serato does not request this new project capability.

## Software validation

The actual unregistered test COM/IASIO DLL exercises an explicit scope. A metadata-only enumeration object releases its final interface, then two fresh audio objects each run setup and streaming I/O, Stop, dispose and release. The simulated worker's complete audit is compared after each stage: **one acquisition, seven clock reads, four audio begin/end pairs and one final release**, including the later two metadata clock refreshes. A competing ASIO object's init and close during a live borrow are rejected before any worker operation. Test-only scope controls are absent from the production DLL; the fixture prevents ordinary COM unload while it holds its explicit owner.

Core tests also verify disposal of idle buffers across facade destruction, invalid-profile rejection without consuming the borrow, explicit close sealing, failed-acquisition sealing, and nonwaiting destruction with a blocked callback. The blocked callback returns through its original planes after facade destruction; no new facade can borrow that sealed owner, and the callback/private process retire independently. Existing default per-object and DLL/code-lease tests remain in the full suite.

One intermediate full run failed in the pre-existing session test's immediate output-enqueue assertion. That version did not retain the returned queue status, so its cause is unproved. Twelve diagnostic repetitions passed without reproducing it. The test client now preserves the same block and retries only the documented `full` result within its existing total deadline, matching the production queue pump's backpressure contract; all other failures retain their numeric status. No PCM, ordering or failure check is dropped, and no deadline is increased. This change does not prove the cause of the earlier intermittent failure or certify production stability.

The final full Release build passed **48/48**. The normal-token read-only source/dependency/signature preflight also passed; its Secure Boot query lacks privileges, so it supplies no fresh security attestation. Reproduce with `scripts/build-native.ps1 -WithAsioComponent`, then run `scripts/export-facade-scope-build.py` for [bound evidence](evidence/facade-scope-build-20261101.json). The complete Release build, sources and records are preserved in `artifacts/build/checkpoints/facade-owner-scope-20261101`; the preceding diagnostic-fix build is separately preserved in `artifacts/build/checkpoints/diagnostic-fixes-20261101`.

All positive transport/timing results here are simulated. Physical native scope reuse, controlled analogue audio, measured timing, the production controller and current Serato admission remain incomplete. No SL3 open, UAC prompt, driver/binding/trust/security change, registration or firmware operation ran for this work.
