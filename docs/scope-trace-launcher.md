# Single-use metadata scope trace launcher

The launcher is intended to reduce the next attended metadata experiment to one administrator approval. The probe remains an ordinary-user process. A separate elevated collector records a sixty-second USB/WPP/state window and before/after recovery evidence. The requested device work remains one acquisition, three facade metadata lifetimes, three clock reads and final release. No audio, setter, firmware operation, retry or persistent elevated broker is introduced.

`prepare-scope-trace.py` reconstructs the complete fixed plan from the current tested build and runtime inputs. It refuses stale or edited plans, consumed attempts and nonfresh contexts. The runtime must explicitly pin both launcher files; an empty or substituted launcher dependency set is rejected. A future collector invocation must match the plan hash, launch ID and normal-role claim, and may create its collector-started marker only once. The PowerShell launcher additionally checks that the waiting normal role is still the same live process by PID, creation time and image.

Default `start-scope-trace.ps1 -Plan <path>` only inspects the plan. Explicit `-Run` is the attended launch path, not an offline verification command. A cancelled administrator launch consumes the attempt; the waiting ordinary role expires without collector admission and must not be rearmed. The collector's internal role refuses an ordinary token and records failure; a repeated invocation cannot overwrite its prior exit evidence.

The new offline checks exercise fixed roles, edited operation/role/context fields, stale runtime, consumed attempts, occupied contexts, invalid locations, missing/mismatched collector claims, hash binding, duplicate collector claims and dependency-set omission/substitution. Separate trace schemas reject controls/scope cross-qualification. Split-role tests verify selection of the scope image and nineteen dependencies rather than the controls probe. Actual process checks exercise default inspection, internal-argument refusal, short-window refusal and normal-token collector denial, including immutable failure evidence.

The elevated launch and physical scope experiment remain unrun. The USB/WPP/state window is not the separate kernel-image-version-qualified window; that integration remains unfinished. The probe exercises the C++ facade owner, not a physical COM/Serato session or calibrated audio timing. See [metadata probe](metadata-scope-probe.md) and [current application boundary](current-serato-integration-decision.md).

## Test stability finding

The first refresh build failed `sl3_device_session_tests` with “Receive retained device reply” after 0.48 seconds. It did not produce a new successful build manifest; the subsequent launcher test correctly refused the stale planner hash. The failed logs are retained locally. Ten consecutive targeted reruns passed. A diagnostic-only test change now emits the command, reply result, elapsed time, worker exit observation and audit stages before cleanup if this recurs. The subsequent complete Release build passed 50/50. The original failure remains unexplained; no timeout, transport behavior or lifecycle requirement was relaxed and no production fix is claimed.

The final full Python suite passes 332/332, including thirteen new launcher checks and one additional scope composition check. Fresh verification, source hashes and exact private-log hashes are recorded in [scope launcher verification](evidence/scope-launcher-verification-20261101.json). This work ran no administrator prompt, USB acquisition, audio, registration, driver installation, binding, trust or security-policy change.
