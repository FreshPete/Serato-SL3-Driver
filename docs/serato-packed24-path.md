# Current Serato legacy ASIO packed-24 path

The unchanged installed/extracted Serato DJ Pro **5.0.0.1278** has an explicit legacy ASIO path for the rebuilt driver's `ASIOSTInt24LSB` sample type. Its tables map type **17** to host format **4**, whose byte-width helper returns **3**. Conditional conversion between that host format and user float format **1** is present in both directions. This narrows a sample-format integration question; it does not admit SL3, select this backend, open our driver or prove real audio.

[Reproducible original-byte evidence](evidence/serato500-packed24-path.json) is generated by [the offline exporter](../scripts/export-serato-packed24-path.py). It checks both installed and extracted executable SHA-256 `66e7af01ddfd151814f51bf44bd8472e5c94f54b3ce12119ef70b7cbab433265`. Inline switch tables are decoded as image-relative data, separately from instructions. No application code executes.

| Checked stage | Original executable finding |
| --- | --- |
| Type identity | Type-name switch `142216A10` selects the literal `ASIOSTInt24LSB` for 17. |
| Host format | `142216B90` maps 17 to 4; `1422158B0` maps format 4 to three bytes and format 1 to four. |
| Optional normalization | Type 17 selects the null-pointer/zero-shift return in both `142217E40` and `142217FA0`; no additional byte-order normalizer is selected. |
| Open | `142217160` forwards input host format in R9D and output host format as stack argument 7 into buffer-processor initializer `142221680`. |
| Input conversion | Initializer selects source host format → user format and stores the converter at processor +`0x28`. For 4 → 1, dispatcher `142223D80` selects initial table entry `143A86BE8` → `142223640`. |
| Output conversion | Initializer selects user format → host format and stores the converter at +`0x48`. For 1 → 4, flag bits 0/1 select four initial table entries. |

The public [PortAudio header](https://github.com/PortAudio/portaudio/blob/master/include/portaudio.h) corroborates the names `paInt24 = 4`, `paFloat32 = 1`, the packed-24 meaning, the non-interleaved high bit and clipping/dithering flag meanings. It does not identify the exact bundled fork/version. The checked local dispatch clears bit 31 before selecting format cases, so the format selector handles the non-interleaved flag separately from the numeric format.

## Input numerical contract

The initial input converter reads bytes at source +0/+1/+2 as little-endian packed 24-bit data, shifts the assembled container left eight bits, converts it as signed int32 to double, multiplies by the exact image constant **2^-31**, then converts to float32. Its derived mapping is:

`float_sample = signed_24_bit_sample / 8388608`

Source strides advance in three-byte units; destination strides in four-byte float units. Seven checked mathematical projections include `000080` → −1, `ffffff` → −1/8388608, `000000` → 0, `010000` → 1/8388608 and `ffff7f` → 8388607/8388608. These are derived from the verified instruction sequence and constant. They are not executed application callbacks, captured audio, converter calibration or a measured signal level.

## Output conditions

The checked float → packed-24 selector uses these **initial PE table values**:

| Low flag bits | Initial function |
| --- | --- |
| 0 | `142222EF0` |
| 1 | `142222DB0` |
| 2 | `142222E60` |
| 3 | `142222D40` |

The no-clip/no-dither variant scales a float by 2^31, truncates to signed int32 and stores the high three bytes in little-endian order. This is not adopted as a new driver conversion policy. Clipping/dithering selection and exceptional/out-of-range float behaviour prevent a general bit-perfect round-trip claim. Runtime replacement of converter table entries is not excluded by reading their initial PE values.

## Integration consequence and limits

The rebuilt ASIO layer already reports packed Int24LSB and preserves the native three-byte containers. This candidate backend therefore supplies a concrete conditional conversion path toward Serato's float buffers; adding a second float-normalization layer inside the driver is not justified by this finding. The [original SL3 driver](clock-control-audio.md) also reported type 17. No source change to the rebuilt transport/ASIO format is needed for this static result.

The earlier [audio selector](serato-audio-routing.md) still requires admitted descriptor/API/name data before a deliberate legacy ASIO connection exists. This investigation does not establish the actual user format or backend chosen for SL3, invocation of these converter functions in a live session, newer JUCE conversion behaviour, account/DVS entitlement, physical channel mapping or audio continuity. [Current integration decision](current-serato-integration-decision.md).
