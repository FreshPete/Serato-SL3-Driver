# Preparing the self-starting ASIO configuration

The install-once route now has a configuration preparation tool. It consumes an existing hash-reviewed native diagnostic bundle and its exact tested build, then writes three fresh records for the [lazy activation entry](asio-activation-entry.md). A native passive inspection mode reads those records through the same configuration loader as the driver. Neither preparation nor inspection constructs an audio session, launches a controller, registers a driver or opens the SL3.

This is a **configuration review**, not a new installable driver package. The original bundle and installed Serato files stay untouched. The session installer cannot consume this review format; its old locator contract is deliberately preserved until persistent installation and recovery have been implemented and tested. It would be incorrect to copy these review files over the installed session configuration.

## Binding and admission

`scripts/prepare-asio-activation-config.py` requires the original bundle manifest identity and exact native build manifest identity. It verifies all current source pins, the successful CTest log, lazy-ASIO lifecycle coverage, production PE exports and the actual native diagnostic DLL/controller identities. The build manifest now separately binds the native configuration inspector image. Simulation-provider exports and simulated controllers remain excluded by the existing deployment verifier.

The generated `sl3-asio.conf` binds the native controller and `sl3-worker.conf` by hash. The worker record binds the native worker, reviewed unchanged USB helper and `sl3-timing.conf`. Timing remains explicitly unmeasured at 44.1 kHz / 128 frames, with a ten-minute lifetime cap. No measurement or production latency approval is invented.

The inspector is the read-only `--inspect-activation` branch of `sl3_driver_configuration_tests.exe`. It loads the entry under the actual diagnostic policy, requires native kind, no existing broker attachment and no assigned runtime output, and checks that the helper has not been loaded. Its exact typed result is required before publishing `review.json`. Only configuration files and the inspector process are involved; no ASIO object or `DriverSession` is created.

The records reference actual review-bundle paths so the native parser can verify real files now. They are location-bound and refer to writable engineering directories, not protected installation paths. Copying them elsewhere does not rebind them. A future persistent installer must generate protected destination records, preserve the original application/profile, support repair/uninstall and prove normal Serato startup. The on-demand activation code will choose its own private per-user runtime output only when audio initialization actually occurs.

## Commands

Run with the existing local analysis Python containing the PE-analysis dependency. The referenced original bundle must have been prepared from the current exact Release build using the existing `prepare-asio-deployment.py --unmeasured-diagnostic` path.

```text
python scripts/prepare-asio-activation-config.py prepare --bundle ABSOLUTE_BUNDLE --bundle-sha256 REVIEWED_BUNDLE_SHA --native-build ABSOLUTE_BUILD_MANIFEST --build-sha256 REVIEWED_BUILD_SHA --output ABSOLUTE_NEW_ACTIVATION_REVIEW_DIRECTORY
python scripts/prepare-asio-activation-config.py verify --output ABSOLUTE_REVIEW_DIRECTORY --review-sha256 REVIEWED_REVIEW_SHA
```

Preparation only admits fresh children under `artifacts/build/activation-reviews`; existing output is preserved. All input/build checks precede creating that review directory. Once writing starts, an I/O or native-parser failure can leave partial files for investigation; only a final valid `review.json` establishes a completed configuration review. Verification rechecks the original bundle, generated bytes, location and native parser. The expected review hash is required. No command here authorizes registration or native acquisition.

## Remaining product boundary

This removes manual record construction from the next experiment, but does not establish normal Serato device selection. It does not supply a persistent Serato profile, bypass a discontinued-device branch, remove the installer-completion workaround or prove SL3 ownership on real restart. Those dependencies still need direct evidence. Phase RCA and timecode vinyl continue to share the same audio path; actual vinyl testing remains open.

## Verified checkpoint

The new Release build passed all **73 CTest checks**. Seventeen preparation/inspection cases passed against actual native diagnostic payloads, including paths containing spaces/Unicode, immutable existing output, wrong bundle/build/review hashes, native refusal of four malformed entry forms, moved-copy refusal and unexpected inventory. The final restored records passed the real command-line verification too. The [metadata-only checkpoint](evidence/asio-activation-configuration-review-20261106.json) binds sources, build/log/inspector identities and generated record identities. Read-only postchecks found original Serato resources, no occupied session paths or temporary registration; no matching test/controller/worker or Serato process remained.
