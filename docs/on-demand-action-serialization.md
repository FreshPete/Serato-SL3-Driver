# One-time setup action serialization

The normal-start setup and restore actions now exclude one another for the same Serato installation. This supports the install-once target; it does not establish that Serato selects the SL3 on ordinary startup. The refreshed [attended candidate](on-demand-normal-start-test.md) remains uninstalled.

Every mutable action holds `userio_resources.bin.sl3-on-demand-action.lock` in the exact protected application directory before component work. Windows creates a new exclusive file object with delete-on-last-close semantics. The implementation checks its identity, permissions, hard-link count and non-reparse path while retaining ancestor handles. An existing object causes refusal: the tool neither opens nor deletes a presumed stale lock by name. Read-only Plan does not acquire a lock, and ordinary-token setup/restore still refuse without requesting elevation.

A parent-only lock would release too early if the coordinator died while its archive helper continued. Each selected PowerShell archive helper therefore receives a scoped duplicate of the same kernel file handle through the explicit child handle list. The helper clears inheritance before executing its body and closes the handle on exit. A surviving helper keeps exclusion after its coordinator dies; the last reference releases it. Native staging retains its existing journal protocol.

All **44 checks pass**: 14 kernel-lock/cohort cases, 17 paired setup/restore cases and 13 real-host preparation/refusal checks. The cohort fixture forcibly terminates only its owned coordinator, confirms its owned PowerShell helper still excludes another action, then signals that helper to finish and verifies subsequent acquisition. Pair tests use actual workspace file replacement and private HKCU fixture registration, including overlap refusal before either component runs. Host checks only plan or refuse; no production setup, elevation prompt, Serato launch or native USB acquisition ran. [Source-bound evidence](evidence/on-demand-action-serialization-20261106.json)

Serialization does **not** turn archive replacement and native installation into one atomic transaction. Component receipts, retained archive witnesses and explicit recovery are still required. The forced-termination test exercises lock lifetime, not a crash inside a production install. This protocol excludes these reviewed actions, not unrelated privileged installers or Serato updaters; keep Serato closed and avoid concurrent installation/update work.
