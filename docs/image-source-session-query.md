# Read-only image-source session query

The future source-only test needs observations independent of PLA's configured XML. `scripts/inspect-image-source-session.py` now calls the documented `ControlTraceW` query operation for one exact private `SL3Image-` session. It can report the effective mode, clock, output filename and loss counters of a live session, or record Windows error 4201 as an absent session. No start, update, flush or stop code is exposed. [Microsoft API contract](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-controltracew).

After the attended GUID rejection, the helper now preserves structurally validated returned properties even when the GUID/name check rejects them. The JSON records `diagnosticAccepted=false`, the validation error and native status; the CLI still exits 1. Native query success means a named source was found, not that its identity was accepted. Non-absence API errors retain unknown activity (`sourceActive=null`) rather than falsely claiming absence. Malformed property layouts remain rejected without publishing unvalidated properties. The returned GUID, identity-match flags and `maximumFileSizeMiB` are visible, while logger handles/kernel pointers stay omitted.

The source-only controller binds each rejected diagnostic filename/hash in `queryRejections`, keeps it out of accepted observations and preserves an unknown owned-source start outcome. It independently checks actual returned identity/status fields; a success exit and acceptance flag cannot override a foreign GUID. Cleanup remains separately governed by its existing persisted-collector admission. None of these changes relaxes identity or source-readiness requirements.

The helper restricts names to the prepared private namespace, rejects zero and legacy kernel logger GUIDs, allocates one bounded 8,312-byte buffer and uses query code zero. It makes no privilege adjustment. On success it checks returned GUID/name, buffer extent and UTF-16 string offsets/termination before publishing fields. The x64 properties header is 120 bytes; the reported mode is at offset 64. Logger handles and kernel pointers are omitted. Returned properties are a point observation, not complete source ownership or continuous coverage evidence.

An actual query of the prepared source `SL3Image-6a8ca986bd8848db92d9c72ca4258c73` returned **4201: absent** on 31 October. The local record is `analysis/image-source-query-absent-20261031-02.json`. It binds the helper's exact bytes and query timestamps. This is a real negative API result; the successful live-property parsing path has only synthetic-buffer tests so far. It does not establish effective system-logger flags, provider enablement, bounded expiry, kernel image rundown or USB readiness.

Eleven helper cases pass with `.venv/Scripts/python.exe -m unittest discover -s tests -p test_image_source_session.py -v`: six parser/identity cases plus five simulated native-query-boundary cases. They cover mode/loss fields, foreign identity/name, invalid strings/buffers, GUID rejection retained through CLI failure, access-denied uncertainty, malformed properties, absence and observed file limits. The API boundary is mocked in those five cases; it exposes only query code zero. Eighteen controller/policy cases also pass, including rejected metadata with both failure and contradictory success exits. A fresh actual read-only query of the now-deleted attended source reports 4201 and produces accepted absence metadata. No source or USB action ran for these checks.

Example for a source whose exact identity came from the [preparation tool](hub-image-source-preparation.md):

```powershell
.venv/Scripts/python.exe scripts/inspect-image-source-session.py --session-name SL3Image-6a8ca986bd8848db92d9c72ca4258c73 --session-guid 1f3e0ee1-ba0b-4d4f-9fd6-ea664175d68d --output analysis/new-source-query.json
```

The output must be a new file. The script never self-elevates. Access-denied, insufficient-buffer and other API errors fail rather than being reported as absence. A successful query with the system-logger bit missing is reported truthfully, not upgraded to a passing configuration.

The [source-only experiment runner](hub-image-source-experiment.md) had an attended run which failed its GUID query and cleaned up; the original returned GUID was not saved. The updated runner now requires a saved committed-service configuration before requesting Start, while this helper preserves any rejected native metadata. Those changes remain software-tested only. Actual live GUID forwarding and independently bounded stopping remain unresolved. The later image rundown applies to its own window and does not close the earlier USB trace's loaded-image gap. This helper supplies observation only; the failed successive USB open remains unresolved.
