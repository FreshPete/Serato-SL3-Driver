# Isolated original-driver timer query

The new explicit `--timer-query` mode sends the original SL3 interrupt command `0x37` with an eight-byte caller-supplied challenge and preserves a genuinely received eight-byte reply. It is a diagnostic step toward the historical driver contract, not a current Serato integration or a replacement for the unresolved release/reopening work.

The worker admits exactly one outgoing 64-byte frame on endpoint `0x01`, then at most four complete 64-byte frames on `0x81`. The existing codec accepts up to three asynchronous notifications before the reply. A fourth notification, bad tag, short transfer, timeout or cancellation fails the query without a retry or fallback. The independent native adapter accepts only the exact challenge frame; it rejects another opcode, challenge, duplicate write or extra read.

The transaction has a 1,500 ms budget, with individual write/read waits capped at 100/300 ms. This budget excludes device enumeration/opening, cancellation and draining, and redirect release. Existing transfer retirement/containment and the process watchdog remain in force. A transfer cannot return normally with pending I/O storage freed. No audio alternate is activated, PCM submitted, rate changed or firmware operation performed. Normal startup, ASIO and IPC do not call this diagnostic.

`timer.json` records intent before redirect opening and each transfer, attempt counts, I/O retirement, parsed response and redirect closure separately. A closed redirect does not establish kernel detachment or readiness for another open. Pre-diagnostic helper/selection failures retain a zero-attempt error record; existing output directories are refused without overwriting their contents. Raw challenges/responses stay in ignored local results. They are not published as authentication evidence.

The [offline comparison](timer-verification.md) still has no runtime call site or embedded vendor key. This diagnostic does not compare the reply with that transform. Its `response_verified`, `serato_admission_verified` and `reopen_ready_verified` fields remain false even after successful parsing. The [missing current DRIVER_API handshake](serato-clock-handshake.md) remains a separate integration requirement; no default handshake or another device identity is substituted.

## Physical test remains pending

The independent macOS [SL3 protocol notes](https://github.com/pepeleedj/Rane-SL3-Macos-ARM-Driver/blob/main/docs/PROTOCOL.md) report that USB playback needs both the per-deck USB switch and recurring `0x37` traffic at roughly 100 ms intervals. [Ben's SL2 test](https://github.com/pepeleedj/Rane-SL2-Macos-ARM-Driver/pull/1) reports a similar dependency on different hardware. Our native silent-output runs confirm transport only. The known-input test stays independent of the timer so its result is attributable to the capture path.

The current single-shot adapter cannot simply be called on each audio callback. One exchange allows up to 1,500 ms and may occupy interrupt IN while waiting for notifications or the matching reply. A periodic playback experiment needs one owner for the interrupt endpoints, one exchange in flight, and separate scheduling from the isochronous queues and ASIO callbacks. Measure actual request and reply spacing on the physical device. A missed deadline should end the experiment and enter cleanup rather than queue a burst of challenges. Keep the driver-liveness exchange separate from any Serato authentication decision.

There is also a framing difference to resolve before periodic use. Our Windows codec emits and checks the original fixed four-byte tag `1c c5 00 01`. The [macOS stream code](https://github.com/pepeleedj/Rane-SL3-Macos-ARM-Driver/blob/main/src/iousbhost_streams.m) increments a little-endian sequence at the same offset and matches replies against that sequence. The 4 November Release executable still passed its inert one-shot plan with the fixed Windows form. Keep that original framing for the first physical check. If testing a sequence variant later, isolate it in the playback diagnostic and verify real echo behavior before changing any existing parser or routing control.

For a later audible experiment, snapshot the actual control table under the retained acquisition before touching routing. Use the verified write/readback path for only the selected deck, keep output initially zero, and independently observe whether a bounded known signal reaches that deck. Restore and read back the original routing before releasing ownership. If restoration cannot be verified, preserve the result as a cleanup failure. A periodic exchange and a routing write are additional operations that the existing one-shot diagnostic does not perform.

## Retained worker integration boundary

The ASIO path still uses `NativeHeldDevice::begin` and `NativeHeldTarget`. The target owns alternate activation and the isochronous backend, while the enclosing device owns the redirect. The session accepts clock and control-table requests only while idle, so the active target is the appropriate owner for a single interrupt loop. The standalone diagnostic's audio thread does not supply that integration.

The retained-worker experiment should explicitly opt in at worker launch and reject combination with the idle control or rate write grants. Start and retire the interrupt loop with the active target, and join it before restoring alternates or accepting another idle interrupt request. Surface interrupt failure separately from audio completion and drive the existing drain path. A native test must exercise Start, Stop and Start again under one redirect, with a fresh audio mailbox each time, and verify no exchanges in the intervening idle interval. This will distinguish reusable stream ownership from the already demonstrated one-second standalone loopback. Preserve the operator's routing table throughout this experiment.

The native broker controller now accepts `--playback-keepalive on` for an explicitly journalled retained worker. It starts the interrupt thread with the audio target, uses a fresh challenge per exchange and schedules one exchange per 100 ms slot. The session drains on timer failure and reports a control failure, including one detected while joining during stop. The thread joins before alternate restoration. Default launches still use the earlier behavior. The combined Release build passed 65 native software checks and three actual CLI refusals for unscoped, unjournalled and simulated invocation. The opt-in path still needs its native Start/Stop/Start test and live ASIO host validation.

The existing native host probe now accepts `--retained-keepalive-44100` with its usual pinned worker/helper and fresh output arguments. It starts two one-second silent streams on one redirect, separates them by a 300 ms idle delay, then releases once. It uses the same native worker keepalive as the broker without requiring a production ASIO registration or an approved timing profile. The retained probe validator's explicit `--keepalive` mode requires two successful, ordered keepalive lifetimes and at least 250 ms between them. The USB trace still needs to corroborate the absence of timer exchanges while idle.

The local retained packet passed preflight with `pwsh -NoProfile -File scripts/start-timer-cadence-trace.ps1 -Plan analysis/retained-keepalive-plan-20261104.json -RetainedKeepalive`. An attended launch adds `-Run` for one separate administrator USB/WPP collector and an ordinary-user host probe. The trace lasts 60 seconds to cover the host probe's watchdog and cleanup. No audio wiring is needed.

The attended retained probe completed both silent streams and closed the single redirect. The live validator initially rejected the journal because its expected sequence omitted the current worker's redirect-owner acquisition markers. The corrected offline validator required both markers and passed the original saved files. It found two keepalive lifetimes, a 329 ms interval between them, and one final release. The trace decoded 27,656 events with no event or buffer loss. The UCX stream device recorded 25 successful 64-byte OUT requests, consistent with three clock reads and 22 timer requests. ## Host callback loopback diagnostic

With SL3 OUT 1/2 wired to IN 3/4 and IN 3/4 set to LINE, the ordinary-user input recorder can run a separate bounded marker test. Use the native Release probe and the hash-pinned worker from the retained keepalive test. Pass absolute paths and a fresh results directory under an existing parent:

```text
sl3_input_record_probe --run-loopback --worker <worker.exe> --worker-sha256 <sha256> --helper <helper.dll> --output <fresh-directory> --expected-rate 44100
python scripts/analyse-timer-loopback.py <result-directory> --host-callback --worker-sha256 <sha256> --output <new-report.json>
```

The probe requires the retained 44.1 kHz acquisition and read-only routing check before it starts. It writes precomputed 997 and 1301 Hz markers into output channels 1 and 2 at callback frame 8192. The tones peak at −30 dBFS and last 650 ms. The recorder keeps three seconds of all six input channels and their callback frame positions. The ordinary capture mode still sends silent PCM.

On this Windows test host, the local packet preflights with `pwsh -NoProfile -File scripts/start-timer-cadence-trace.ps1 -Plan analysis/host-callback-loopback-plan-20261104.json -HostLoopback`. After confirming the RCA wiring, the attended invocation adds `-Run`. One administrator approval starts the passive 60-second trace. The ordinary-user probe waits for fresh collector evidence, and the runner checks trace cleanup and the SL3's resting state afterward. Preflight does not open the SL3 or play the markers.

The analysis Python environment needs NumPy. Before estimating offsets it checks the worker hash, callback positions and bank alternation, PCM digest, and journal sequence from acquisition through release. The report estimates the offset from callback placement to the returned envelope and gives frequency fits for input channels 3 and 4. Inspect both fits and their separation before interpreting the offsets. This round-trip observation combines callback buffering, the shared queues, native USB transport and the analogue path. Separate input and output measurements are still needed for the production timing profile. The diagnostic uses the host session directly and has no ASIO registration prerequisite.

Do not run it as an automatic startup probe or immediately after a failed redirect. First resolve the [ordinary-user phase observation](hub-port-observer.md) or establish a reviewed ownership design for the known second-open stall. A future physical result must bind its challenge, response, trace, executable identity, cleanup and selected recovery. It must still be reported separately from key verification, current Serato admission, analogue audio, DVS and stability testing.
